## 图例

本文线框图用于确认信息层级和空间关系，不代表最终颜色、字体或像素级视觉稿。

本轮已经确认的 Dashboard、Global Search Palette、项目目录、项目看板单行工具栏、看板列与 Issue 卡片使用完整 App Shell 线框图：左侧始终画出固定 Product Sidebar，右侧再画当前 Page Canvas。Global Search Palette 打开时也保留完整外壳，只把侧栏与右侧页面一起放到模糊、压暗的背景层。后续尚未逐项确认的页面目前仍是 Page Canvas 草图，进入评审时按同一方式补全侧栏。

```text

▸               可展开区域
│ Inspector │   可折叠或可调整宽度的侧面板
```

桌面端优先目标尺寸为 `1440 × 900`，同时覆盖 `1024 × 768`。移动端覆盖 `375 × 812` 和 `430 × 932`。

## 全局桌面外壳

当前顶部 Navbar 与左侧 AppBar 会争夺产品导航。新结构改为固定分区式 Product Sidebar 和独立 Page Canvas，不再设置横跨产品的全局顶部导航。侧栏固定展示产品入口、完整项目列表和完整会话列表；点击具体对象后只更新右侧 Page Canvas。

- A、B 和 E 固定，不随当前项目或会话变化。
- C 和 D 完整展示当前环境中的所有项目与会话，不截断数量，也不提供“查看更多”。
- 两个列表都按真实 `updated_at DESC` 排序；点击、浏览或聚焦列表项不能写入更新时间。
- 当前项目或会话使用稳定高亮表示，不额外置顶，也不占用所谓“快捷配额”。
- 项目与会话都是单层对象入口，不在侧栏中展开仓库、分支、任务、消息或 Diff。
- 项目和会话名称使用单行省略，聚焦或 hover 时通过 Tooltip 显示完整名称与必要上下文。

| 列表行为   | 项目                             | 会话                               |
| ---------- | -------------------------------- | ---------------------------------- |
| 展示范围   | 当前环境全部项目                 | 当前环境全部会话                   |
| 排序       | 真实 `updated_at DESC`           | 真实 `updated_at DESC`             |
| 当前对象   | 保持高亮，不改变排序             | 保持高亮并显示运行状态，不改变排序 |
| 点击结果   | 右侧打开项目页面                 | 右侧打开 Agent 工作台              |
| 数据量较大 | 增量加载或虚拟化，逻辑列表仍完整 | 增量加载或虚拟化，逻辑列表仍完整   |
| 加载失败   | 分区内显示重试，不阻断其他区域   | 分区内显示重试，不阻断其他区域     |

两个分区标题只承担分组和排序提示，不设计折叠开关，避免用户误以为内容丢失。列表滚动到底即代表已经访问全部对象，不再跳转另一份“完整列表”。

#### 分区标题的视觉层级

参考截图的空间层级，但不复制其内容：`项目`、`会话`属于弱化的分组标签，不应与 Dashboard、搜索等导航项争夺注意力。

```text
项目                         12px / 16px · Medium · text-low
  ■ vibe-kanban              13px / 18px · Regular · text-normal
  □ qm                       13px / 18px · Regular · text-normal

会话                         12px / 16px · Medium · text-low
  ● 重构前端菜单             13px / 18px · Regular · text-normal
  ○ Runtime review           13px / 18px · Regular · text-normal
```

- 分区标签使用更淡的 `--text-low`，字号比菜单项小一档，不设置 active 背景。
- 分区之间主要使用 16px 上间距和 6–8px 下间距区分，不给每个分区增加卡片、底色或粗边框。
- 分区右侧若出现数量或 `＋`，与标题使用同一字号和颜色；交互元素在 hover/focus 时提升为 `--text-normal`。
- 不通过降低整个分区的 `opacity` 制造淡色，否则图标、焦点环和状态信息也会一起失去对比度。
- 小字号淡色文字在浅色和深色主题下仍必须达到 WCAG AA `4.5:1`。

#### 固定区与滚动区

完整项目与会话列表可能远高于视口，因此侧栏不能作为一个整体滚走：

```text
┌────────────────────────┐
│ A. 身份 / 环境         │  固定顶部
├────────────────────────┤
│ B. 产品入口            │  固定
├────────────────────────┤
│ C. 完整项目列表        │  ┐
│ D. 完整会话列表        │  ├─ 共用中间纵向滚动区
│                        │  ┘
├────────────────────────┤
│ E. 设置 / 用户 / 版本  │  固定底部
└────────────────────────┘
```

中间区域出现滚动条时，项目和会话分区标签使用 sticky 定位保持方向感；滚动事件停留在侧栏内，鼠标离开后 Page Canvas 继续独立滚动。提供“跳到主内容”的键盘入口，避免键盘用户需要逐个越过长列表。

#### 左侧工作台与右侧页面结构

产品只保留一列固定工作台侧栏。项目和会话本身就在这列侧栏中，Page Content、Page Tabs 和 Inspector 都是右侧内容区域，不再承担另一套纵向导航。

```text
整个应用
├─ 左侧 Product Sidebar（始终固定）
│  ├─ Dashboard
│  ├─ 搜索（打开 Global Search Palette）
│  ├─ 项目
│  ├─ 工作流
│  ├─ 智能体
│  ├─ 完整项目列表（updated_at DESC）
│  └─ 完整会话列表（updated_at DESC）
│
└─ 右侧 Page Canvas
   └─ Page Content（随左侧选择变化）
      ├─ Page Tabs（可选，同一对象的视图切换）
      └─ Inspector（可选，当前选中对象的详情）
```

| 区域            |          典型宽度 | 负责什么                                    | 不放什么                                             |
| --------------- | ----------------: | ------------------------------------------- | ---------------------------------------------------- |
| Product Sidebar |             256px | 切换产品模块，完整展示项目和会话对象        | Provider、MCP、Issue、项目设置等对象内部菜单         |
| Page Content    |          剩余宽度 | 标题、操作、列表、看板、对话和编辑器        | 重复左侧项目或会话列表                               |
| Page Tabs       | Page Content 内部 | 切换同一会话或 Workflow 的不同视图          | 切换其他产品模块或其他对象；项目看板不使用 Page Tabs |
| Inspector       |         320–480px | 展示当前选中 Issue、文件、Diff 或配置的详情 | 常驻产品入口和完整管理菜单                           |

项目模块的实际路径如下：

```text
左侧项目列表：选择 vibe-kanban
    ↓
页面内容：vibe-kanban 项目看板
[搜索]                         21 Issues [＋ 新建 Issue]
    ↓ 选择一个 Issue
Inspector：Issue 属性、状态、关联运行和 Diff
```

智能体模块沿用同一结构：

```text
左侧产品入口：智能体
    ↓
页面内容：[Provider] [模型] [MCP] [Skills] [Commands] [原生配置]
    ↓ 选择一个配置
Inspector：配置来源、差异和详细属性
```

边界规则可以概括为：左侧固定呈现产品入口和全部项目、会话，右侧呈现当前选择的内容与对象内部功能，二者之间不再插入一列菜单。

#### 56px 折叠图例

```text
┌──────┐
│  V   │  产品 / 环境
│      │
│  ▦ 2 │  Dashboard（active 示例）
│  ⌕   │  搜索
│  □   │  项目
│  ⇄ 1 │  工作流
│  ◇ ! │  智能体
│      │
│ ──── │
│  ⚙   │  设置
│  ☺   │  用户 / 版本
└──────┘
  56px
```

折叠由用户主动控制，不因 hover 自动展开。项目和会话列表在 56px 模式下通过点击项目或会话图标打开 Drawer，Drawer 使用与桌面侧栏相同的数据和排序；不能用 hover 浮层作为唯一入口。每个图标都必须具有可访问名称，并在 hover 或键盘聚焦时显示文字提示。

#### 菜单项状态图例

```text
默认       ◇ 智能体            可进入，无未处理状态
Hover      ░◇ 智能体░          只提供视觉反馈，不展开菜单
Active     ▌◇ 智能体           当前路由属于该产品域
Current      ■ vibe-kanban      当前项目或会话列表项
Focus      ┏◇ 智能体┓          清晰、持续可见的键盘焦点环
Badge      ▌⇄ 工作流    3      聚合数量，不呈现对象明细
Degraded   ◇ 智能体      !      Provider 或工具存在异常
Disabled   ◇ 智能体             功能确实不可进入，并可查看原因
```

- Active 表示产品模块，Current 表示具体项目或会话，两层状态可以同时存在，但必须使用不同的视觉强度和无障碍状态。
- 搜索是覆盖层触发器，不进入 Active 状态；弹框打开时保留背景页面原有的 Active 和 Current 状态。
- Focus 不能被 active 背景吞没，当前项也不能只依赖颜色区分。
- Badge 使用固定占位，超过一位数可显示 `9+` 或圆点，避免菜单横向跳动。
- Degraded 仍然可以进入对应模块查看诊断；只有确实无法进入时才使用 Disabled。

| 产品入口  | 徽标表达的内容                               |
| --------- | -------------------------------------------- |
| Dashboard | 全局待处理总量或最高严重级别                 |
| 搜索      | 不显示常驻徽标                               |
| 项目      | 需要用户处理的项目级异常，普通任务数量不显示 |
| 工作流    | 活跃运行和等待关卡的聚合数量                 |
| 智能体    | 不健康的 Provider、MCP、Skill 或配置数量     |

会话列表项可以显示 Running、等待输入、等待审批、失败和空闲状态，但状态不能只靠颜色，必须同时使用图标形状或文本提示。列表只按真实 `updated_at` 排序：运行事件确实更新会话时可以重排，单纯点击、浏览和选中不能重排。

### 外壳尺寸建议

| 区域                   |      默认 |   收起 | 规则                                                            |
| ---------------------- | --------: | -----: | --------------------------------------------------------------- |
| 分区式 Product Sidebar |     256px |   56px | 桌面展示完整侧栏；紧凑模式由用户主动收起，不使用 hover 自动展开 |
| 侧栏项目列表           |  全部项目 | Drawer | 真实 `updated_at DESC`，当前项目只高亮、不置顶                  |
| 侧栏会话列表           |  全部会话 | Drawer | 真实 `updated_at DESC`，当前会话只高亮、不置顶                  |
| Page Canvas 内容区     |  剩余宽度 |      — | 自己拥有标题、上下文、横向 Page Tabs 和操作                     |
| 页面标题区             |   72–96px |      — | Contained 页面进入最大宽度容器                                  |
| Inspector              | 320–480px |    0px | Full-bleed 页面使用，可拖动并完全关闭                           |

### 左侧工作台侧栏规则

- 产品入口顺序固定为“Dashboard、搜索、项目、工作流、智能体”，设置、用户和版本固定在底部系统区。
- “搜索”与 `Ctrl/Cmd + K` 打开同一个 Global Search Palette，不跳转路由、不替换 Page Canvas，也不在 256px 侧栏中常驻输入框。
- 项目区和会话区不设数量上限，统一按真实 `updated_at DESC` 排序，不提供“查看更多”。
- 当前项目或会话只使用 current 高亮；点击和浏览不能更新 `updated_at`，加载时保留固定行高，避免侧栏跳动。
- 列表项只显示名称、必要图标和状态，不展开树形子菜单，也不加载仓库、分支、任务、消息或运行详情。
- Product Sidebar 的身份、产品入口和系统区固定，中间项目/会话区域在高度不足时独立滚动。
- 列表投影加载失败不能阻断产品入口；对应分区显示精简错误和重试入口。
- active 产品入口与 current 项目/会话是不同层级；深层页面通过路由同时恢复模块和对象上下文。

### 右侧页面规则

- Page Canvas 不增加纵向菜单列；Page Tabs 只负责同一对象的不同视图。
- 智能体、工作流和设置的分类使用横向 Page Tabs、页内分组或筛选控件。
- 对象、Page Tab、筛选和标签必须进入 URL，刷新、深链接和浏览器返回后仍能恢复。
- Product Sidebar 是项目和会话的唯一常驻列表，不在右侧维护第二份选中状态；Global Search Palette 提供跨模块直接跳转。

### 两种主内容宽度

```text
Contained：Dashboard / 项目目录 / 智能体中心 / 设置等普通页面

┌─ Product Sidebar ─┬────────────────────── Page Canvas ──────────────────────┐
│ 固定 256px         │                                                        │
│                    │      自动留白   ┌──── 最大 1120px ────┐   自动留白      │
│                    │                 │ 页面标题与说明        │                 │
│                    │                 │ 搜索与页面操作        │                 │
│                    │                 │ 网格、列表或表单      │                 │
│                    │                 └──────────────────────┘                 │
└────────────────────┴────────────────────────────────────────────────────────┘

Full-bleed：看板 / Agent 工作台 / Workflow / Arena

┌──────────────────────────────────────────────────────────────────────┐
│ 页面标题与操作     │ 当前对象 Page Tabs                               │
├───────────────────┴──────────────────────────────────────────────────┤
│ 使用全部可用宽度，可包含 Split Pane 和 Inspector                      │
└──────────────────────────────────────────────────────────────────────┘
```

Contained 内容相对 Product Sidebar 右侧的 Page Canvas 水平居中，而不是相对整个浏览器窗口居中，也不是在页面中上下居中。页面从顶部开始，标题、搜索或工具栏、网格、列表和表单都进入同一个容器，不能出现“标题撑满、主体单独居中”的两套边界。桌面使用 `width: min(100% - 48px, 1120px)`；窄屏页边距降为 16px。`1120px` 只是最大宽度，容器本身不等于一张带背景和阴影的大卡片。只有确实需要横向工作空间的生产力页面使用 Full-bleed。

## Dashboard（总览）

> 2026-10-19 更新：[Agent 运行监控台设计](../session-dashboard/README.mdx)已实现为横向监控表，仅展示进行中的工作，区分 Task 执行、工作流与独立会话，并展示真实状态、最新回复和项目 / 目录元信息。本节保留早期设计背景；当前交互、实现范围与验证结果以新设计及其实施计划为准。

### Dashboard 页面规则

| 区域     | 规则                                                                                          |
| -------- | --------------------------------------------------------------------------------------------- |
| 页面标题 | 不提供“新建工作区”或其他创建按钮；工作区从项目、Issue 或会话上下文创建                        |
| 全局统计 | 按项目、Issue、智能体运行分成三个紧凑文本组；不拆成占据首屏的大型 KPI 卡片                    |
| 需要处理 | 按等待审批、等待输入、失败与阻塞排序，默认最多显示 6 条；每行提供一个直接恢复动作             |
| 活跃运行 | 默认最多显示 5 条，使用稳定表格行；流式更新状态和持续时间，不实时重排用户正在操作的行         |
| 智能体   | 展示连接状态、默认模型、API 地址和运行数量；整行进入对应智能体详情，不在 Dashboard 内编辑配置 |

等待审批、等待输入、取消和失败等 Agent 状态必须来自 canonical AgentRun 投影。点击关注事项或活跃运行行进入其 canonical 深链接；返回 Dashboard 时恢复原滚动位置。各分区使用固定上限的摘要投影，不提供“查看全部”，也不在当前页无限展开。

智能体摘要必须来自 Provider adapter 的规范化配置投影：未显式配置模型时显示“跟随客户端默认”；API 地址默认只显示域名，自定义地址增加“自定义”标记，并通过可聚焦 Tooltip 展示移除凭据和查询参数后的完整地址。API Key、Token 和 URL 内嵌凭据不得进入 Dashboard 投影或 DOM。

| 维度       | 指标     | 口径                                                               |

| ------------- | ---------------------------------------------------------------------- |

### 内容与行为边界

| 项目     | 规则                                                                                                                         |
| -------- | ---------------------------------------------------------------------------------------------------------------------------- |
| 入口     | 左侧“搜索”和 `Ctrl/Cmd + K` 唤起同一个弹框；重复触发不能叠加多个实例                                                         |
| 搜索范围 | 功能入口、配置项、Codex、Claude Code、Gemini、Oh My Pi、MCP、Skills、Commands、原生配置、项目、会话、Issue、工作流和运行记录 |
| 分组     | 使用“智能体 / 配置 / 工具 / 功能与对象”等弱化小标题；分组只帮助扫描，不形成新的导航层级                                      |
| 结果行   | 主行显示名称和可选状态，副行显示所在路径；命中词高亮不能破坏可读性或注入 HTML                                                |
| 打开     | `Enter` 或点击后进入结果的 canonical 路由并关闭弹框                                                                          |
| 动作     | 首版只打开和跳转，不直接删除对象、停止运行、修改配置或执行其他风险动作                                                       |
| 状态     | 查询和高亮项仅在弹框打开期间存在；不写入 URL，不创建搜索历史路由，也不改变背景页面 active/current 状态                       |

搜索遵循 Product Sidebar 顶部的当前 Local / Remote 环境，不在同一结果列表中静默混入另一环境的数据。无输入时展示常用功能、四个智能体和常用配置；输入后以 `150–250ms` 防抖查询，并取消过期请求。结果区独立滚动，但弹框本身始终保留输入框和底部键盘提示。

弹框打开后焦点直接进入输入框，`↑` / `↓` 移动高亮结果，`Enter` 打开，`Escape` 关闭。弹框使用 `dialog` 与 `aria-modal` 语义，输入和结果使用可访问的 combobox/listbox 关系；关闭后焦点返回侧栏搜索项或发起快捷键时的原聚焦元素。高亮结果必须同时提供可见背景、焦点指示和屏幕阅读器选中状态，不能只靠颜色。

| 状态          | 弹框表达                                                             |
| ------------- | -------------------------------------------------------------------- |
| Initial       | 常用功能、四个智能体和常用配置，不显示空白结果区                     |
| Searching     | 保留旧结果并显示行内进度；超过 300ms 才出现 Skeleton，避免输入时闪烁 |
| No results    | 显示当前查询，建议检查拼写或改用功能、配置、智能体和对象名称         |
| Partial error | 标记失败的数据源并允许单独重试，其他分类结果继续可用                 |
| Offline       | 本地环境继续搜索可用索引；Remote 结果标记离线和上次更新时间          |

桌面弹框建议宽约 `680px`，最大高度为 `min(600px, 70vh)`，使用统一 Overlay z-index token、`8px` Backdrop Blur 和 40–60% Scrim。模糊覆盖搜索框后的整个 App Shell，包括 Product Sidebar 与 Page Canvas，不能只降低背景透明度；不支持 `backdrop-filter` 时使用更强 Scrim 作为降级。进入和退出只使用 `150–250ms` 的 opacity/transform 动效，并尊重 `prefers-reduced-motion`。在窄屏上改为全屏 Dialog，搜索框和结果保持单列，触控目标至少 44px，软键盘不能遮挡当前高亮结果或关闭入口。

### 工作台交互规则

- 会话创建后不提供切换 Agent 的操作。
- Agent 状态、审批、输入和取消来自 canonical AgentRun 投影。
- 工作台可以由 Product Sidebar 会话列表或 Issue 中的单 Agent Task 标题进入；两者解析到同一 canonical 页面和同一份会话状态。
- Product Sidebar 在整个工作台生命周期内保持同一分区结构，并将当前项目和会话列表项标记为 current。
- 项目和会话切换只发生在 Product Sidebar；搜索、归档、导入和其他管理动作进入对应右侧页面，不复制常驻列表。
- 中间主区始终显示 canonical 对话时间线和固定输入框，不渲染“对话 / 变更 / 文件 / 终端”Page Tabs，也不让辅助内容替换整个主区。
- Inspector 默认记住用户上次打开的标签和调整后的宽度，支持向右侧完全收起；窄屏时自动收起。
- 变更、文件、Git、终端和预览只使用右侧同一个 Inspector 容器，避免与主区重复入口或形成层层弹窗。
- 标题区第一行只显示任务名称；没有关联任务的独立会话使用会话名称。第二行依次显示可选 Issue、工作空间路径和分支，并整体使用低强调样式。
- Issue 可点击返回对应详情；没有关联 Issue 时直接省略且不保留空占位。长路径使用中间截断，hover 或键盘 focus 时显示完整值并提供复制入口。
- Agent、模型、canonical 运行状态、持续时间和停止操作不进入标题区，由对话输入区域附近的运行上下文承载。
- canonical 时间线存在待处理 Agent 交互事件时，在对话时间线和页面顶部都出现明确入口，但共享同一个底层请求状态；页面顶部只负责定位，不维护第二套操作逻辑。
- 当前 Agent 不支持某项能力时，保留入口并说明原因，不静默消失。

### Agent 原生交互事件

审批、输入请求、失败恢复和冲突等内容只在 Agent Runtime/Adapter 提供对应 canonical 事件时出现。工作台使用统一的 `AgentInteractionEvent` 视觉容器承载底层内容，但不在前端定义 Agent 应该何时提问、请求哪种权限或提供哪些恢复动作。

```text
待处理
┌────────────────────────────────────────────────────┐
│ {底层事件类型与状态}                               │
│ {底层提供的标题、说明和上下文}                     │
│ {底层提供的输入控件}        {底层提供的可用操作}   │
└────────────────────────────────────────────────────┘

已处理
✓ {底层事件摘要} · {底层最终状态}
```

UI 只负责容器层级、间距、状态样式、输入期间的本地表单状态、操作中的加载反馈以及完成后的紧凑历史形态。用户提交操作时，UI 将底层提供的动作原样交回 canonical API，并以返回状态更新展示；不能自行生成允许、拒绝、重试或其他按钮，也不能自行判断操作风险、修改 Provider 原生语义或用乐观状态假装事件已经完成。

不同 Agent 可以返回不同内容与操作，`AgentInteractionEvent` 按实际能力渲染。底层没有提供交互动作时，事件保持只读；能力暂不可用时展示底层原因，不用猜测出的替代动作。事件处理完成后仍保留在 canonical 时间线中，仅视觉上压缩为一条可追溯记录。

新事件到达时使用非抢占式提示和可访问的状态播报，不强制滚动或抢走用户焦点。控件保持底层给出的顺序，支持键盘操作、可见焦点和明确标签；等待、完成、拒绝与失败不能只靠颜色区分。顶部关注入口与时间线组件指向同一个 canonical 事件，点击只负责定位到该事件。

```text
└──────────────────────────────────────────────────────────────┘
```

`＋` 打开包含全部四个分类的菜单；工具栏中的 Commands 和 Skills 分别直接打开对应分类，但仍保留左侧分类菜单，方便继续切换。MCP 是 Agent 级工具能力，不作为逐条消息资源出现在 Composer 分类中；分类动作可以跳转到 Command 管理或 Tool Manager，但不能在选择器内复制完整管理页面。

分类通过点击或键盘打开，不能依赖 hover。上下方向键在当前结果中移动，左右方向键在分类菜单与结果面板之间切换，`Enter` 选择，`Escape` 关闭整个选择器并保持正文不变；焦点状态和当前分类都必须清晰可见。右侧结果区独立滚动，切换分类时保持面板尺寸稳定。

空间不足时先水平翻转两块面板，再降低可用高度并让结果区滚动，不能越出视口或覆盖主要发送操作。移动端改为单面板逐层进入，选择分类后显示结果，并提供明确的返回分类入口，不把两个面板横向压缩到窄屏。

粘贴普通文本或大量代码时保持原文，不自动格式化或转换成文件；可以提供由用户主动选择的“作为附件发送”。粘贴图片或文件时才创建附件并进入偶现扩展区，显示上传、完成、失败、重试和移除状态。

未发送内容按 canonical 会话独立保存草稿。切换项目、会话、Inspector 或异常刷新后恢复对应文本和附件；只有 canonical API 确认接收后才清空，发送失败时完整保留。恢复草稿不能重新提交已经成功发送的消息。输入框拥有独立可访问名称，不能只用 Placeholder 充当标签。

`Enter` 发送，`Shift + Enter` 换行；输入法组合尚未完成时，`Enter` 只完成选字而不发送。只有 Agent Adapter 返回明确上下文限制且输入接近限制时才显示提示；前端不猜测模型限制、不常驻显示无意义计数，也不静默裁剪文本。

底部工具区永久存在。Agent 在会话创建后只读；模型、推理、权限、停止及其他控件只有底层提供对应能力时才可操作，否则按真实状态只读或说明不可用原因。`＋` 打开完整资源分类，Commands 与 Skills 入口分别直达相应分类，`@`、`/`、`$` 提供相同选择器的快捷路径；列表内容、可用性和调用语义完全来自当前 Agent Adapter。控件过多时将低频项收入更多菜单，主要输入与发送操作不能被挤出可视区域。

#### 底部工具栏分组

`ComposerToolbar` 始终为单行，分为左侧输入配置区和右侧运行操作区，中间使用弹性留白隔开。

```text
┌──────────────────────────────────────────────────────────────────────┐
│ [＋] [Codex] [gpt-5.6⌄] [高⌄] [受限⌄] [/命令] [$技能]  ● 12:43 [■] [↑] │
└──────────────────────────────────────────────────────────────────────┘
       输入配置与能力                              运行反馈与操作
```

左侧依次放置添加入口、只读 Agent 身份以及底层实际支持的模型、推理、权限、Commands 和 Skills。添加、只读 Agent 身份和发送入口始终存在；其他项只在当前 Agent 存在对应概念时出现。某项能力存在但因当前运行状态暂不可修改时保留禁用控件，并在 hover、focus 和触屏说明中给出底层原因；Provider 根本不存在该概念时不制造占位控件。

权限控件只显示当前摘要，点击后在 `ComposerAccessoryArea` 展开完整临时配置 UI。Commands 和 Skills 入口向输入区上方打开同一个级联资源选择器并直达对应分类；需要继续填写参数时，再将参数 UI 挂载到偶现扩展区。Agent 身份没有下拉箭头，也不能通过工具栏更换。

右侧依次显示低强调运行状态与持续时间、条件出现的停止操作和固定在最右侧的发送操作。发送与停止是两个独立按钮，不能相互替代；运行时能否发送仍由底层能力决定。停止只在 canonical 能力可用时出现，发送提交中提供进度并阻止重复触发。

工具栏不能换行或产生水平滚动。宽度不足时先把低频 Agent 特有配置收入更多菜单，再将 Commands 和 Skills 缩为仍有 Tooltip 与可访问名称的 `/`、`$` 入口；添加、主要运行操作和发送始终保持可见。桌面控件使用紧凑高度，触屏环境扩大实际点击区域而不改变视觉层级。

#### 发送、排队与停止

Composer 始终允许编辑草稿；发送按钮根据 Agent Runtime/Adapter 当前提供的动作语义显示“发送”“追加”或“加入队列”。运行中不接受消息或连接异常时，按钮禁用并在附近说明底层原因，但输入、附件和草稿保存继续可用。

| 底层当前能力   | UI 动作                    | 草稿处理               |
| -------------- | -------------------------- | ---------------------- |
| 可以立即发送   | 发送                       | 接收确认后清除本次快照 |
| 可以追加到运行 | 追加                       | 接收确认后清除本次快照 |
| 只支持排队     | 加入队列                   | 入队确认后清除本次快照 |
| 不接受新消息   | 禁用发送并说明原因         | 保留并持续保存         |
| 连接异常       | 禁用发送并显示连接恢复状态 | 保留并持续保存         |

前端不能在底层没有队列能力时偷偷维护一套发送队列。canonical 队列存在时可以在 `ComposerAccessoryArea` 展示数量、内容和底层提供的管理动作；没有队列时该 UI 不出现。发送、追加或入队期间只锁定本次发送快照和对应动作，防止重复提交；用户继续输入的内容作为下一份草稿保留，不能在回执到达时一起清空。

只有 canonical API 确认接收后，本次快照才进入时间线并从 Composer 移除。失败时恢复完整文字与附件，在 Composer 附近显示原因和重试入口。成功回执、重连和页面刷新都不能导致同一快照重复发送。

发送固定在最右侧，停止位于其左侧；两个操作独立存在且不能互相替代。点击停止直接调用 canonical cancel，不增加确认弹框；按钮进入“停止中”并阻止重复点击，只有 canonical Run 进入 `cancelled` 才展示已停止。传输失败时恢复停止入口并提供重试，停止不能清空草稿、附件或会话，底层如何处理队列也完全以 canonical 返回状态为准。

运行持续时间、发送和停止都不使用前端假超时。Agent 可以长期运行；停止请求未完成时继续显示 canonical 状态，不能因为等待时间长就由 UI 猜测成功或失败。审批和原生输入请求仍在对应 `AgentInteractionEvent` 内处理，不能临时把普通输入框改造成另一份审批表单。

固定区域必须为最后一条消息预留底部空间，不能覆盖时间线内容。移动端输入区随虚拟键盘上移并保持发送与停止操作可见；所有图标按钮具有可访问名称、稳定点击区域和可见焦点。

### Inspector 收起状态

```text
展开
┌──────────────────────┬──────────────────────────────────┬──────────────────────┐
│ Product Sidebar      │ ConversationPane                 │ Inspector            │
│                      │                                  │ 变更 / 文件 / 终端   │
└──────────────────────┴──────────────────────────────────┴──────────────────────┘

收起

```

收起动作让 Inspector 整体向右退出且内容宽度归零，不残留空白栏。最右侧的低强调把手覆盖在页面边缘，不占用对话布局宽度；点击后恢复上次标签、宽度和内容状态。收起 Inspector 不会停止 Agent、终端或预览服务。键盘焦点会在收起按钮与重新打开把手之间正确转移，并尊重减少动态效果设置。

## 工作流编辑器

```text
┌─────────────────────────────────────────────────────────────────────────────────────────────┐
│ Product Sidebar │ ← 工作流 / 发布流程     Draft · 已保存   [添加 Node] [验证] [保存] [运行] │
├─────────────────┼───────────────────────────────────────────────────────────────────────────┤
│ Dashboard       │                                                                           │
│ 搜索            │                         ┌──────────────┐                                  │
│ 项目            │                         │ Start        │                                  │
│ 工作流          │                         └──────┬───────┘                                  │
│ 智能体          │                                │                                          │
│                 │                      ┌─────────▼─────────┐                                │
│ 项目列表        │                      │ Type: Agent        │                                │
│ ……              │                      │ 分析需求           │──────┐                         │
│                 │                      │ Claude Code        │      │                         │
│ 会话列表        │                      └───────────────────┘      │                         │
│ ……              │                                      ┌────────▼─────────┐                │
│                 │                                      │ Type: Agent       │                │
│ 设置 / 版本     │                                      │ 实现功能          │                │
│                 │                                      │ Codex             │                │
│                 │                                      └────────┬─────────┘                │
│                 │                                               ▼                          │
│                 │                                           [End]                          │
└─────────────────┴───────────────────────────────────────────────────────────────────────────┘
```

画布中的业务单元统一叫 Node，不再使用 Agent Step、执行块或步骤等平行名称。Node 卡片最多显示三层：弱化 Type 与可选“待配置”、唯一主标题、可选执行者摘要。Task 是 Node 承载的任务，Agent 是 Task 的执行者；承载 Task 时主标题直接读取 `Task.title`，不能再增加重复 Task 摘要。Issue 发起的 Task 与 Node 承载的 Task 读取同一种 Task 模型。

Node Type 保留 `Start`、`End`、`Agent`、`Condition`、`Human Gate`、`Transform` 和 `Arena`。类型只作为 Node 卡片中的弱化标签以及配置弹框中的字段，不进入 Node 名称。例如对象始终叫“分析需求”，旁边弱化显示 `Type: Agent`，不能显示为“Agent Node”或“Task Node”。

Start 和 End 由 Workflow 自动创建且各自唯一，不出现在“添加 Node”的选择入口中。两者不允许删除、复制、改名或显示配置内容；点击只选中和定位，并关闭此前打开的配置框。Start 禁止入边，End 禁止出边。

`Arena` 类型的 Node 与其他承载 Task 的 Node 一样只使用一个主标题。第三行仅显示“N 个候选”摘要，多个 Agent 名称只在 Node 配置弹框和运行详情中展开，不能在画布上把同一个 Node 拆成多条 Task，也不能在 Issue 卡片中生成多条同级任务。

```text
┌────────────────────────┐
│ Type: Agent     待配置 │  小号、淡色；状态仅在必要时出现
│ 分析需求               │  唯一主标题
│ Claude Code            │  仅承载 Task 时显示执行者摘要
└────────────────────────┘
```

模型、Skills、耗时、工作区路径、Session 和其他运行细节均不进入 Node 卡片。Condition、Human Gate、Transform 等不承载 Task 的类型不保留空白第三行；卡片高度按实际层数自然收敛。

普通 Node 桌面宽度固定为约 `220–240px`，用户不能手动拉伸。两层和三层卡片高度随内容自然变化；主标题最多两行，溢出省略，并在 hover 或 keyboard focus 时显示完整标题。Start / End 使用更紧凑的系统卡片，不占用普通 Node 的完整宽度和空白行。

Node 不按 Type 使用七种整卡底色。全部卡片使用相同中性表面，Type 只在第一行通过淡色小字或小图标区分；hover 轻微增强边框，selected 使用品牌色描边与轻阴影。待配置卡片使用淡警示边框，同时保留右上“待配置”文字；被选中时两种状态同时可见，不能用 selected 样式覆盖校验提示。

运行页沿用同一张卡片，只替换 Meta row 右侧状态：

```text
┌──────────────────────────┐
│ Type: Agent    ● Running │
│ 分析需求                 │
│ Claude Code              │
└──────────────────────────┘
```

状态必须同时使用图标或状态点与文字。只有 Running 的小状态点可以轻微呼吸，Waiting、Failed、Completed、Cancelled 等均为静态；整张卡片不闪烁、不持续发光。边框只使用低强度状态色，中性表面保持不变，selected 外描边独立叠加。编辑页不显示运行状态，只显示必要的“待配置”；减少动态效果模式将 Running 状态点改为静态。

编辑器不设置常驻节点库或右侧 Node Inspector。“添加 Node”打开 Node Type 选择入口；点击已有可配置 Node 或 Edge 打开同一个靠右浮动的 Workflow Canvas 配置 Dialog。它覆盖画布但不挤压或平移画布，与 Page Canvas 顶部、右侧和底部保留明确间距，因此不能实现成贴边 Drawer。节点运行状态只在运行视图中持续动效；模板编辑时保持克制，重点是结构和配置可读性。

创建流程在选择 Node Type 的瞬间完成 Node 的 Draft 插入：系统用该 Type 的稳定默认值创建 Node，立即将其显示在画布、自动选中并打开配置弹框。编辑已有 Node 时直接打开同一个弹框。Type 固定显示在弹框标题区且不可编辑，避免切换 Type 时隐式丢弃 Task、Agent、类型配置或破坏已有 Edge。

```text
添加 Node
   └─ Node Type Picker
      ├─ 取消（尚未选择 Type）──▶ 不创建 Node
      └─ 选择 Type ────────────▶ 默认值创建并写入 Workflow Draft
                                   └─ 画布立即显示并自动选中
                                      └─ 打开配置 Dialog
                                         ├─ 配置完整：正常 Draft Node
                                         └─ 配置不完整：显示“待配置”
```

```text
┌──────────────────────────────┐
│ 选择 Node Type               │
│ ◇ Agent          一行用途说明│
│ ◇ Condition      一行用途说明│
│ ◇ Human Gate     一行用途说明│
│ ◇ Transform      一行用途说明│
│ ◇ Arena          一行用途说明│
└──────────────────────────────┘
```

Picker 是锚定在页面“添加 Node”按钮或 connection-drop 落点旁的小浮层，不是居中大 Modal。五项纵向排列，每项只使用小图标、名称和一行说明；不提供搜索框、分类、Tabs 或 Start / End。方向键切换选项，Enter 选择，Escape 取消；取消后焦点回到触发按钮，或回到发起临时连线的来源 Node。

#### 连线驱动建图

```text
连接到已有 Node

┌────────────┐   拖动连接点               ┌────────────┐
│ 分析需求   │ ●~~~~~~~~~~~~~~~~~~~~~~~~▶ │ 实现功能   │
└────────────┘                            └────────────┘
        合法目标高亮 + 松手立即创建 Edge

连接到空白画布

┌────────────┐
│ 分析需求   │ ●~~~~~~~~~~~~~~~┐
└────────────┘                 │ 临时连线保持来源上下文
                               ▼
                    ┌─────────────────────┐
                    │ 选择 Node Type      │
                    │ Agent               │
                    │ Condition           │
                    │ Human Gate          │
                    │ Transform / Arena   │
                    └─────────────────────┘
                       ├─ 取消：不修改 Draft
                       └─ 选择：原子创建 Node + Edge
```

连接点在 Node hover、selected 或 keyboard focus 时显示，不能常驻成强视觉噪声；开始连线后目标 Node 的整块可用区域提供扩大命中，但视觉尺寸不跳动。合法目标使用轻量边框与连接点反馈，非法目标显示原因；松手到非法位置时预览线回弹，不创建再删除一条临时 Edge。

多出口 Node 不再共用一个没有含义的圆点。连接点直接放在对应语义行末，并以短标签说明这条线会产生什么路由：

```text
普通 Node        ── ● Default

Human Gate       ── ● Approve
                 ── ● Reject

Condition        ── ● 分支 A
                 ── ● 分支 B
                 ── ＋ 新增分支

Arena            ── ● Winner

Start            ── ● Default
End              无输出连接点
```

普通连接点只在 hover、selected 或 keyboard focus 时增强；Human Gate 与 Condition 的语义标签随连接点一同出现，避免只靠位置或颜色区分。从哪个连接点开始拖动，就在创建 Edge 时确定对应路由类型，不再打开第二层选择。Condition 的“新增分支”保持低强调，开始连接后才创建待配置 branch；取消连接时不留下空 branch。已连接连接点仍保持可发现，用户可以拖动 Edge 端点重连。

同一语义连接点支持自然展开多条连线，语义生效后全部目标并行执行：

```text
                    ┌─▶ 测试功能
Default ●───────────┼─▶ 更新文档
                    └─▶ 创建 PR
```

连接点已有连线时，再从圆点拖动仍然是“新增 Edge”；拖动某一条线的 source / target 端点才是“重连该 Edge”。多条线分别可以选中、删除和撤销，删除其中一条不会改变同一连接点上的其他目标。第一版不为这种并行关系增加 Fork Node。

连线视觉使用平滑曲线，而不是直角折线路径：

```text
             ╭──────▶ Node A
Node ●───────┼──────▶ Node B
             ╰──────▶ Node C
```

示意图中的聚合形态只表达多条曲线从同一点自然散开，实际 Edge 不共享可点击的公共主干；每条线都拥有自己的完整命中区、选中状态和端点。终点使用小箭头表达方向。默认连线低强调，hover 或 selected 时只突出当前 Edge，其他 Edge 轻微弱化，避免复杂 Workflow 中所有路径同时争夺注意力。Node 卡片始终在 Edge 图层上方，曲线自动生成且不提供手动路径编辑或“重置路径”；一般流程出现遮挡时直接移动 Node。

```text
Human Gate ●── Approve ─────▶ 发布
Condition  ●── 测试通过 ────▶ 创建 PR
普通 Node ●────────────────▶ 下一步
```

Default Edge 不显示常驻标签。Approve、Reject、Winner 和 Condition branch 的小型淡色标签靠近来源连接点，不占据线条中间区域；hover 或 selected 时当前标签增强并显示完整语义。普通路径因此保持安静，特殊分支仍然可以直接辨认。

```text
编辑态       Node ─────────────▶ Node       静止
正在传递     Node ──·─·─·─·───▶ Node       轻微定向流动
已经经过     Node ━━━━━━━━━━━━▶ Node       低强调高亮
未命中分支   Node ┈┈┈┈┈┈┈┈┈┈┈▶ Node       进一步弱化
```

运行时连线只回答“执行走了哪里”。Failed、Waiting、Completed 等状态继续显示在 Node 上，不在线条上增加重复 Badge 或文字。页面处于编辑状态时不播放任何 Edge 动画；减少动态效果模式把“正在传递”替换成静态强调线，不能通过取消动画同时丢失当前路径反馈。

空白落点 Picker 锚定在释放位置，临时线保持可见但不进入 Workflow Draft。选择 Type 后新 Node 在落点附近通过 overlap avoidance 定位，使用稳定默认值创建并自动选中、打开 Node Form；取消、Escape 或点击 Picker 外部都只取消临时连接。页面“添加 Node”仍可独立打开同一 Picker，但没有来源连线。

```text
拖 Node 到已有 Edge

来源 ───────────────▶ 原目标
          ▲ Edge 扩大命中区高亮
          │ 放下「检查代码」
          ▼
来源 ──原路由语义──▶ 检查代码 ──Default──▶ 原目标

拖 Edge 端点

来源 ─────────▶ 旧目标  ──拖动 target──▶ 新目标
```

Edge 拆分只在拖动 Node 松手时原子提交，移动经过 Edge 但未在高亮命中区放下不会改变连接。第一段继承原路由语义和 source handle，第二段使用 Default 并继承原 target handle；Condition branch 的表达式保持不变，只把目标更新到插入 Node。拆分、连接和重连各形成一个 history command，Undo 完整恢复原 Edge 与 Node 位置。右键菜单不再显示“插入 Agent Step”或“插入 Node”。

新建和编辑 Node 的字段变化都直接更新内存中的 Workflow Draft。点击画布中的另一个 Node 立即切换配置内容，关闭配置框只改变可见性，不撤销修改，也不删除待配置 Node；只有显式删除才移除 Node。页面顶部继续显示未保存状态，只有“保存 Workflow”才统一校验并持久化 Node、Edge 和整个 Workflow；存在待配置或无效 Node 时阻止保存并定位错误。配置框不再设置“应用到草稿”或“取消编辑”按钮。

删除普通 Node 不打开确认 Dialog。Node Form 删除按钮、画布 Delete 键和上下文菜单删除调用同一个 Draft command：先捕获 Node、Task 配置、位置、全部关联 Edge 和受影响 Condition branches，再原子移除并关闭配置框。Start / End 的所有删除入口都必须不可用，而不是只隐藏某一个按钮。

```text
删除「实现功能」
        ↓
立即从 Workflow Draft 移除 Node + 3 条关联 Edge + 对应分支投影
        ↓
清除 selection + 关闭配置框 + 焦点留在画布
        ↓
Toast：已删除「实现功能」及 3 条连线  [撤销]
        ↓
撤销：原子恢复受影响图片段，不覆盖其后的无关 Draft 编辑
```

```text
Workflow 编辑器 · 未保存
        ↓ 离开编辑器 / 切换 Workflow / 进入非编辑页面
┌────────────────────────────────────────┐

```

这是独立的模态确认 Dialog，不复用右侧非模态配置外框。打开后保留原目标导航，使用 Scrim、Focus Trap、Escape 和可预测的焦点返回；“继续编辑”与 Escape 都取消导航。“不保存”恢复最后持久化 Graph 后进入原目标；“保存并离开”复用页面顶部保存命令，只有校验和请求成功才继续导航，失败时留在编辑器并定位错误。

切换 Node / Edge、关闭配置框、单击或拖动画布等编辑器内部操作不触发离开确认。浏览器刷新、关闭标签页或窗口时只使用原生 `beforeunload` 提示；产品不能伪造自定义浏览器关闭 Dialog，也不能假设异步保存一定能在关闭前完成。

#### Revision-aware 保存

```text
页面顶部点击“保存”
        ↓
捕获不可变 Draft revision 18 ───────▶ 提交 revision 18
        │
        └─ 画布和配置框继续可编辑
                    ↓
              当前 Draft revision 19

revision 18 保存成功
        ├─ 当前仍为 18 ──▶ Clean / 已保存
        └─ 当前已为 19 ──▶ persisted baseline = 18 / 仍然 Dirty
```

保存进行中只锁定重复保存请求，不锁画布、Node / Edge selection 或表单字段。旧 revision 的成功响应不能重新挂载 Graph、覆盖 revision 19，或把页面错误标记为 Clean；失败同样保留当前 Draft。顶部保存状态通过紧邻按钮的文字和 `aria-live="polite"` 呈现“保存中 / 已保存 / 保存失败”，但不抢焦点、不使用阻断式 Toast。viewport、selection、配置框、Body `scrollTop` 和正在编辑的字段焦点在响应前后保持稳定。

#### Undo / Redo

```text
Workflow 页面顶部
┌────────────────────────────────────────────────────────────┐
│ Workflow 名称      [↶ 撤销] [↷ 重做]   未保存   [保存]     │
└────────────────────────────────────────────────────────────┘

一次拖动 Node ───────────────▶ 1 个 Move Node command
一次连接或重连 ──────────────▶ 1 个 Edge command
一次字段聚焦编辑 ────────────▶ 1 个 Config command
删除 Toast 的“撤销” ─────────▶ 同一个 History.undo()
```

顶部图标保持低强调，提供 Tooltip、快捷键说明、可见焦点和真实 disabled，不增加历史列表或侧栏。焦点在文本输入框内时，`Ctrl/Cmd + Z` 与平台原生行为一致；焦点在画布或非文本控件时才进入 Workflow command history。一次拖动不能按每个 pointer move 生成历史记录，连续字段输入也不能按每个字符膨胀历史。

历史只保留到本次 Workflow 编辑会话结束。保存不清空历史，只更新 persisted baseline；保存后撤销会重新显示 Dirty。Undo 后产生新的 command 会清除 Redo 分支。删除 Toast 出现后若又提交新 command，旧 Toast 关闭，保证 Toast 的撤销始终等价于顶部和快捷键的最近一次 Undo。

```text

        ↓  上下文菜单“复制 Node” / 画布 Ctrl/Cmd + D
```

副本在来源 Node 右下方使用稳定偏移并经过防重叠定位，不能完全覆盖来源。承载 Task 的 Node 修改 canonical `Task.title`，不额外生成 Node 名称；不承载 Task 的 Node 才修改自身名称。复制后 selection 只包含新 Node，右侧共享外框直接显示它的 Node Form。

桌面端配置框宽约 `400–480px`，高度不超过 Page Canvas 扣除上下间距后的可用高度。外框四边都有 `12–16px` 圆角和统一浮层阴影；Header 固定，Body 独立滚动，底部只允许显示非操作性的 Draft 状态，不设置固定操作 Footer。打开与关闭仅使用 `160–220ms` 的 opacity 与轻微横向位移，不从视口边缘整块滑入，并尊重 `prefers-reduced-motion`。

Node 和 Edge 只复用外框，不复用业务表单：选中 Node 时显示 Node、Task、Agent 和 Type 配置，选中 Edge 时用独立 Edge 表单替换 Header 与 Body。对象切换期间外框保持原位置、原宽高、圆角和阴影，不执行关闭再打开，也不叠加第二个配置浮层。

```text
配置框关闭 ──点击可配置 Node──▶ 外框进入 + Node Form
Node A ──点击 Node B─────────▶ 外框不动 + Header / Body Crossfade
Node  ──点击 Edge────────────▶ 外框不动 + 替换为 Edge Form
Edge  ──点击 Node────────────▶ 外框不动 + 替换为 Node Form
当前对象 ──快速连续选择───────▶ 中断前一动效 + 只显示最后选择
当前对象 ──选择 Start / End────▶ 关闭配置框 + 保留系统 Node 选中定位
当前对象 ──显式删除────────────▶ 关闭配置框 + 不自动选择相邻对象
当前对象 ──单击画布空白────────▶ 清除 selection + 关闭配置框
当前对象 ──拖动画布空白────────▶ 保留 selection + 保留配置框 + 平移画布
```

内部切换使用可中断的 `120–160ms` Crossfade，不动画外框 width、height、top 或 right，也不使用大幅横向滑动。`prefers-reduced-motion` 下直接替换内容。每个 Node / Edge 在当前编辑会话中独立保存 Body 滚动位置；首次打开的对象从顶部开始，切回时恢复离开位置。点击画布对象只更新 selection 和内容，不强制把焦点送入配置框；异步加载超过 `300ms` 时仅对应分区显示 Skeleton，Header 和外框保持稳定。

空白单击和空白平移不能只靠事件目标区分。交互在 pointer gesture 结束后复用画布现有的 canonical drag threshold：位移未超过阈值才执行清除 selection 和关闭配置框；超过阈值则只完成平移，并保留当前 selection 与配置框。不能在空白 `pointerdown` 时提前关闭，也不能为配置框单独定义另一套距离或时间阈值。

配置框打开时不添加 Scrim、Backdrop Blur 或全画布 Pointer Overlay。未被配置框遮挡的画布保持正常亮度和完整交互，用户可以连续执行平移、缩放、拖动以及选择 Node / Edge；配置框与画布分别保留清晰的 hover、selected 和 focus 状态。配置框表面不做点击穿透，避免操作表单时误触其下方 Node。

共享 Dialog 不设置内部 Tabs。Header 固定，Body 独立滚动，不设置“取消 / 应用”操作 Footer；Node Form 中的 Node、Task、Agent 和 Type 专属配置使用单列分区，不适用的分区完全隐藏，Edge Form 独立维护 Edge 配置和操作。字段错误紧邻原字段展示，不能只在配置框顶部汇总。参考图只用于确定浮动位置和外框关系，不复制其中的业务内容、Tabs 或字段。

连接方向在 Header 和只读连接摘要中展示，不提供来源、目标下拉框。重连属于画布端点操作，平滑路径由 Node 位置自动生成，不提供手动路径调整；Edge ID、source / target handle 与内部路径数据不进入常规表单。删除操作与普通内容分隔并置于 Body 底部危险区。


删除不增加确认 Dialog；短时 Toast 使用 `aria-live="polite"` 宣告且不抢键盘焦点。“撤销”恢复完整 Edge，而不是用默认值创建一条看似相同的新连线。删除与撤销都只改变 Workflow Draft，页面顶部“保存 Workflow”仍是唯一持久化入口。

字段修改立即投影到 Node 卡片和 Workflow Dirty 状态。刚按默认值创建但尚未完成必要配置的 Node 使用文字状态“待配置”，不能只靠颜色表达。字段可以在编辑过程中短暂处于无效状态，错误在 blur 后就地出现且不能阻止用户切换 Node；页面级“保存 Workflow”负责执行完整校验，并在存在待配置或无效 Node 时阻止持久化、定位对应 Node。

承载 Task 的 Node 直接使用 `Task.title` 作为画布和 Dialog 标题，不再显示独立 Node 名称字段。Condition、Human Gate 和 Transform 等不承载 Task 的类型才在基础分区编辑 Node 名称。Header、运行记录和会话始终读取同一个 canonical 标题。

## 工作流运行页

```text
┌─────────────────────────────────────────────────────────────────────────────────────────────┐
│ 发布流程          Waiting input          3 / 5 完成                         [取消运行]       │
├─────────────────────────────────────────────────────────────────────────────────────────────┤
│                                                                                             │
│                      ┌───────────── Workflow Canvas ─────────────┐                           │
│                      │ Start → ✓ 分析需求 → ● 实现功能 → Review │  ┌─ 需要处理 ───────────┐ │
│                      │                                 → End     │  │ Review 正在等待批准   │ │
│                      └───────────────────────────────────────────┘  │ [打开对应 Node]        │ │
│                                                                     └───────────────────────┘ │
│                                                                                             │
└─────────────────────────────────────────────────────────────────────────────────────────────┘
```

运行页没有“总览 / 画布 / 节点会话 / 事件”Tabs，画布就是唯一主体。Header 不重复运行统计卡，只保留名称、canonical 状态、完成数和当前可用的取消动作。等待输入、等待审批或失败时，右侧关注卡覆盖画布但不压缩或重排画布；卡片只包含最需要处理的事项和“打开对应 Node”，正常运行或全部完成时完全不渲染该卡，也不保留空白侧栏。

点击 Node 是进入该 Node 会话或运行详情的唯一主入口。全局技术事件仍可从二级运行详情访问，但不常驻在 Page Tab、Dashboard 或右栏列表中。关注卡与 Node 卡片读取同一 canonical runtime projection，不能根据原生日志自行猜测等待或失败状态。

点击运行画布中的 Node 后，在画布右侧浮动显示详情，而不是立即离开 Workflow：

```text
┌─────────────────────────────────────────────────────────────────────────────────────────────┐
│ Workflow Canvas                              ┌ 实现功能 · Running ──────────────── × ┐      │
│                                              │ Agent                              │      │
│ Start → 分析需求 → 实现功能 → End            │ Codex · 已运行 12 分钟              │      │
│                                              │                                    │      │
│                                              │ 当前输出 / 等待事项 / 错误          │      │
│                                              │                                    │      │
│                                              │ [打开完整会话]                     │      │
│                                              │ [技术事件 ▾]                       │      │
│                                              └────────────────────────────────────┘      │
└─────────────────────────────────────────────────────────────────────────────────────────────┘
```

详情框沿用编辑配置框的右侧留白、完整圆角和浮层阴影，但不复用可编辑 Node Form。它无 Scrim、无 Focus Trap，不改变画布尺寸或 viewport；单列 Body 只渲染当前 Type/状态适用内容，不设置内部 Tabs。Agent 显示“打开完整会话”，Arena 显示“查看候选结果”，技术事件默认折叠。从关注卡点击事项时，关注卡直接被对应 Node 详情替换，不能叠出两个右侧浮层；关闭详情后保留原画布位置与 Node selection。

Human Gate 等待决策时，详情 Body 直接显示用户提示，底部按配置显示 `[批准继续]` 或 `[拒绝] [批准继续]`。点击后两个动作共同进入处理中状态，避免重复决策；成功后原位显示新的 canonical 状态，失败则在动作旁说明原因并允许重试。Agent 的输入与权限请求不复制到这里，仍通过“打开完整会话”完成。

## Arena 对比页

Arena 的首要目标是横向比较，不应把每个候选压成互不关联的小聊天窗口。

```text
┌─────────────────────────────────────────────────────────────────────────────────────────────┐
│ Arena · 修复取消状态              3 个候选 · 2 完成       [综合结果] [停止全部] [⋯]        │
├──────────────────────────────┬──────────────────────────────┬───────────────────────────────┤
│ Codex                        │ Claude                       │ Gemini                        │
│ (Completed 18m)              │ (Running 21m)                │ (Completed 16m)               │
├──────────────────────────────┼──────────────────────────────┼───────────────────────────────┤
│ 摘要                         │ 摘要                         │ 摘要                          │
│ 修改 8 个文件                │ 正在运行测试                  │ 修改 5 个文件                 │
│ +184 / -73                   │ +220 / -91                   │ +96 / -41                    │
│                              │                              │                               │
│ [打开会话] [Diff] [测试]     │ [打开会话] [Diff] [测试]     │ [打开会话] [Diff] [测试]      │
│                              │                              │                               │
│ ○ 候选                       │ ○ 候选                       │ ● 选择为获胜方案              │
└──────────────────────────────┴──────────────────────────────┴───────────────────────────────┘
```

并列区只展示可比较结果，不渲染完整对话正文；“打开会话”进入该候选的 canonical Session。可用宽度内最多同时展示三个候选；候选超过三个，或屏幕无法保持至少两个可读候选列时，切换为支持方向键的候选选择区加固定对比摘要，一次展开当前候选详情，不进行横向无限滚动。

点击“综合结果”会启动一个新的综合 Agent 工作区，并立刻以“综合 · Running”加入候选集合；完成后它拥有与其他候选相同的摘要、Diff、测试、完整会话入口和“选择为获胜方案”。综合结果不覆盖原候选，也不会自动获胜。若新增综合结果使候选超过三个，页面沿用同一候选切换规则，不额外叠加综合结果面板。

点击任一“选择为获胜方案”后，Arena 背景使用 Scrim 与 Blur，中央只出现一个紧凑确认框：

```text
┌──────────────────────────────────────────────┐
│ 将 Gemini 设为获胜方案？                 [×] │
├──────────────────────────────────────────────┤
│ Gemini · Completed                           │
│ 变更 5 个文件 · +96 / -41                    │
│ 将归档另外 2 个候选工作区                    │
│ 确认后应用到主工作区，并继续 Workflow        │
├──────────────────────────────────────────────┤
│                         [取消] [应用并继续]   │
└──────────────────────────────────────────────┘
```

确认框不嵌入完整 Diff，也不要求再次选择候选。初始焦点落在“取消”，Escape 与关闭按钮都返回原“选择为获胜方案”；提交后“应用并继续”显示进行中并锁定页面全部 winner 按钮。失败时确认框保留候选与影响摘要，在动作附近显示原因和重试；成功后才关闭，并由 canonical winner 状态更新候选列。非 Workflow 场景不显示“继续 Workflow”等并不会发生的影响，CTA 使用对应的明确采用文案。

```text
更多菜单
┌────────────────┐
│ 关闭本轮       │
├────────────────┤
│ 解散并归档     │
└────────────────┘
```

图中因为 Claude 仍在 Running，所以显示“停止全部”；没有可取消的真实运行时该按钮不占位。点击后必须对全部可取消候选发出 canonical cancel，并在操作进行期间防止重复提交、逐项投影最终状态，不能只把 Arena 标记为已关闭。“关闭本轮”保留结果和工作区，只改变 Arena 生命周期；“解散并归档”使用 danger 样式并在二次确认中明确将归档工作区、删除 Arena。两项低频操作都位于更多菜单。关闭页面或切换路由不触发这些动作，Arena 在后台继续运行。

## 设置页

设置使用横向 Page Tabs、页内分组和独立内容页，不继续采用越来越大的单一 Modal，也不增加纵向菜单列。

```text
┌─────────────────────────────────────────────────────────────────────────────────────────────┐
│ 设置                                                          当前主机：Local ▾             │
│ [通用] [当前主机] [Cloud]                                                                  │
├─────────────────────────────────────────────────────────────────────────────────────────────┤
│ 外观                                                                                        │
│ Theme       System / Light / Dark                         首次启动：System                  │
│ Density     Compact / Comfortable                                                          │
│ Font scale  100%                                                                           │
│                                                                                             │
│ 通知与数据                                                                                  │
│ 通知偏好 / 数据目录 / 备份                                                                  │
│                                                                                             │
│ 行为                                                                                        │
│ Default IDE   VS Code                       Update channel   Stable                         │
│                                                                  [恢复默认] [保存]         │
└─────────────────────────────────────────────────────────────────────────────────────────────┘
```

Dark-first 是整套视觉设计的基线，不是强制用户首次进入深色主题。没有已保存偏好时，`System` 根据操作系统解析为 Light 或 Dark，并在系统主题变化时同步更新；显式选择 Light 或 Dark 后则保持固定。切换主题不刷新页面、不丢失当前路由、草稿或滚动位置，根主题必须在首屏绘制前完成解析，避免先亮后暗或先暗后亮的闪烁。

Light 与 Dark 分别验证 Page Canvas、Sidebar、Dialog、Popover、选中/悬停/焦点/禁用状态，以及 Markdown、代码块、Diff、终端和状态色。System 复用解析后的 Light/Dark Token，不维护第三套视觉变量。

全局颜色职责保持简单且固定：

```text
品牌层：橙色 → 产品身份 / 页面唯一主操作 / selected 与 focus
状态层：蓝 / 黄 / 绿 / 红 / 灰 → Running / Waiting / Success / Error / Cancelled
```

状态必须继续配合文字或图标，不能只靠颜色。品牌橙不填满普通卡片、用户消息或大面积页面背景；对象被选中且同时处于运行、等待或失败状态时，橙色 selection ring 与状态标识分别存在，不能互相覆盖。

## 响应式规则

| 宽度          | 布局                                                                           |
| ------------- | ------------------------------------------------------------------------------ |
| `>= 1440px`   | 256px 分区式侧栏，完整项目与会话列表共用中间滚动区，右侧直接显示页面内容       |
| `1024–1439px` | 224px 分区式侧栏，完整列表保持可用，Inspector 默认收起或覆盖                   |
| `768–1023px`  | 56px 产品图标栏；项目/会话使用复用完整数据的 Drawer，Inspector 使用独立 Drawer |
| `< 768px`     | 五项底部导航；项目/会话使用 Drawer 或全屏对象选择器，不新增纵向菜单列          |

响应式不是简单隐藏信息。被移出的内容必须有明确入口，关键操作不能只在桌面 hover 中存在。
