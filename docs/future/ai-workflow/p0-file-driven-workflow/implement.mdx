| 实际 CLI 联调          | Codex/Claude Code 真实读写文件、主 Agent 工具被发现并调用、一次完整交付可追踪          | F8       |

补充部分交付验收：

- 无明确请求时不启动部分汇总；用户或主 Agent 正式提交后，汇总实际读取准确成果文件及缺失项清单，交付标为部分完成，原失败事实不被改写。
- 无关任务仍在执行时不抢占或自动取消；旧运行真实收尾后按队列执行，重放不重复创建汇总，引用文件缺失或无可用成果时如实报错。
- 页面、主会话和外部 API 对交付完整性的表达一致；汇总节点成功不能自动将业务任务标成全部完成。

并行失败与部分汇总规则已确认，验收必须同时核对文件内容、执行历史、页面与 API 的交付完整性。不以 mock、提示词中写了“请读文件”或 Agent 自称读过作为真实联调完成依据；应结合执行记录、可观察工具证据与实际文件内容核对，证据不可见时明确未覆盖。

本次联调仅构建受影响的 debug/test 目标，正式包通过 GitHub Actions/npm 发布链路构建与验证；推送 `main` 会自动触发 `publish-easy-npx.yml`。

## 4. 验证约束与记录方式

验证使用仓库已有格式化、类型、后端/前端定向测试入口。只跑受影响包和新增用例，不盲目全 workspace 编译；按实际 target 记录命令，不能将零匹配视为通过。使用现有 Rust/MSVC 工具链，单路 Cargo、关闭增量及调试符号，target 放在 C 盘临时目录，避免继续占满 F 盘。真实联调通过 `VK_DEV_ASSET_DIR` 使用独立临时数据库和审计目录。

高风险点：旧 `each` 与新批次重复触发、同节点任务身份冲突、系统轮次与用户消息争抢、取消和领取竞争、文件/DB 受理不一致、部分汇总错误清除失败事实。失败回退停用新受理入口并保留执行记录/文件，不清库、不删除成果、不复活已停止执行，不增加双任务存储兼容层。按用户指令提交并推送 `main` 后，正式发布由 GitHub Actions/npm 自动执行。

本页维护实际改动、运行命令、结果及证据；完成判断依据已有实现、定向自动回归及核心真实联调，未执行场景不记为测试通过。2026-10-14 用户确认不要求追加扩展实机验证；原完整 HTTP、其他提供方、异机及安装验证保留为覆盖记录，不再阻塞本任务完成。历史结果见[历史运行时设计](../runtime-control-design.md)。

### 5.1 实际实现

- `crates/workflow/{files,dispatch}.rs`：项目相对路径、原子文件、SHA-256、任务清单/分工协议、固定候选与阶段依赖校验。
- 新迁移和 `workflow_files` / `workflow_handover` DB 模型：仅保存文件绑定、内部子任务、批次、真实执行关联、自动接力和完整性记录。
- `workflow_runtime/{file_handoff,batch_runtime,agent_launch,recovery}.rs`：普通工作流文件交接、并行独立会话、按阶段推进、一次汇总、持久失败和原执行恢复。
- `workflow_runtime/{management,batch_rework,handover}.rs`：第七个 scoped MCP 工具 `workflow_dispatch`，原主会话的真实 System 分工轮次，精确重试及显式部分汇总。
- 共用文件预览组件、工作流批次/子任务/文件入口与七种语言文案；页面与外部查询使用相同完整性投影，类型由 Rust 生成。
- 收尾修复：部分汇总保留成功来源；未执行过的依赖允许首次分配会话，已删除原会话则继续拒绝替换；实例删除核对真实停止，队列恢复与 Retry 防止同会话重复进程。
- 实际联调修复：审计关闭只更新真实存在的列；重复 Cancel 保留第一次完整命令，不因诊断文本变化重复受理；读后写的 WAL 事务先取得写锁，避免 Agent 事件并发投影时立即报数据库锁定。
- 原生协议修复：Claude 成功结果中的 `api_error_status: null` 不再误判为错误；主会话保存统一的 `CODEX` / `CLAUDE_CODE` 等执行身份，启动校验继续严格匹配。
- 文件协议说明：拆分说明不自行定义后续交接索引；执行者遵循 Runtime 提供的准确五字段协议，状态和哈希仍由 Runtime 验证及记录。
- 停止收尾：同一持久停止意图在命令失败或进程未确认退出时保持待处理，由后台继续重试；完整来源边界确认后才完成意图并释放项目占用。自然成功已提交时，清理不改写成果、状态或完成时间。
- 输出管道收尾：Codex 控制连接会持有适配器输出管道，真实子进程退出不等于这根管道关闭。宿主在排空前释放已结束的控制连接，并停止未完成的适配器任务；自然 OS 退出保留末尾协议输出。审计失败和已提交业务结果仍分别记录。
