## 实施范围

依据[已确认的设计](./file-handoff-design.mdx)实施第一版，沿用当前工作流引擎、管理工具、节点会话和共享会话浮框。

| 部分     | 改造内容                                                   | 主要代码入口                                              |
| -------- | ---------------------------------------------------------- | --------------------------------------------------------- |
| 文件交付 | 按工作流、运行和节点执行隔离控制文件，保留五字段交付清单   | `file_handoff.rs`、`file_context.rs`、`workflow/files.rs` |
| 依赖调度 | 等齐本轮有效输入，识别实际条件路径，防止重复汇总           | `workflow/planner.rs`、`runner.rs`                        |
| 异常处理 | 提供真实文件现场，排队交给原主 Agent，通过现有管理工具处理 | `handover.rs`、`management.rs`、工作流 MCP                |
| 用户界面 | 使用现有运行投影说明等待、处理和成果，打开准确的原会话     | 工作流运行模型、画布和会话浮框                            |

用户停止不能触发恢复；普通成功节点不额外启动主 Agent。失败执行保留历史，新的处理采用新的执行身份，成功的其他成果须通过文件核对后复用。

本轮不实现跨服务重启后自动接管存活 CLI，不开放普通任务或单智能体动态构造工作流，不新增聊天实现、同步节点或固定错误升级表。

## 实施顺序

1. 建立统一的工作流运行目录和实际文件引用，更新节点交付指令及读取入口。
2. 改造普通节点汇合规则，与条件路径、拆分批次和结果复用对齐。
3. 扩展现有持久接力和管理请求，打通异常材料、原主会话、处理指令及新执行。
4. 接入现有界面和共享类型，完成针对性检查并记录验证边界。

## 核心验收

| 场景                   | 必须观察到的结果                                           |
| ---------------------- | ---------------------------------------------------------- |
| 普通两节点串行         | 第一节点真实执行成功且文件验收通过后，第二节点读取准确文件 |
| A、B 并行后汇总        | A 先完成不能启动汇总；A、B 都交付后只启动一次              |
| 条件只选 A             | 汇总等待 A，不等待明确未选择的 B；条件未决定时不能提前跳过 |
| B 失败或交付不合格     | 保留 A 成果，汇总不启动；原主会话收到具体现场              |
| 主 Agent 提交处理      | Runtime 受理新执行，保留原失败和会话，继续校验新的交付     |
| 重复事件或请求         | 复用原受理身份，不重复启动节点或主 Agent                   |
| 主会话忙碌或用户停止   | 忙碌时等待；停止后旧事件不能重新启动工作                   |
| 查看节点、交付物和历史 | 读取准确来源；打开页面、浮框不创建或启动执行               |

### 检查限制

`cargo clippy -p workflow -p db -p local-deployment -p server -p mcp --lib --locked --no-deps` 已完成，退出码为 0，仍有告警。

严格 Clippy 未通过：本轮未修改的 `workflow/dispatch.rs` 存在 `field_reassign_with_default`，此外执行底座等模块仍有既存告警。全库未使用翻译键检查仍报告五个既存键：`createMode.managedDirectory.label`、`createMode.managedDirectory.description`、`createMode.headings.repoStep`、`modelSelector.requested`、`modelSelector.custom`。这些结果不能计为全库 lint 通过。

本轮未运行真实多智能体 CLI 的端到端验收，也未触发发布构建。自动化通过证明上述调度、文件、数据库和界面约束；不同 CLI 在真实任务中是否始终按要求交付文件，需要另行实际运行验证。跨服务重启接管存活 CLI 仍在本轮范围之外。
