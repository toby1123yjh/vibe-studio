## 1. 沿用画布右侧浮框

点击具体 Agent 工作，打开画布已有的右侧非模态浮框。桌面约 `440px` 宽，上、右、下各留约 `24px`；浮框叠放在画布上，无 Scrim 或背景模糊，画布继续支持点击、平移与缩放。关闭和切换浮框不触发画布自动 fit 或压缩。

原来的 `WorkflowRunNodeDetailsDialog` 已使用 `FloatingPanel`，主要承载节点详情和“打开完整会话”入口。本方案保留该外层形态，把已有会话的消息、工具与输入组件接进来。

**复用的是会话能力与组件，浮框和完整会话页使用同一个 Session。** 不把整个 `WorkspacesLayout`、产品侧栏或双栏 Workbench 塞进浮框，也不照着原组件另写一套消息、输入和发送逻辑。

## 2. 浮框里面放什么

```text
┌─────────────┬────────────────────────────────────────────────────────┐
│ Vibe Kanban │ 工作流名称 / 当前运行状态                              │
│ Dashboard   ├────────────────────────────────────────────────────────┤
│ 搜索        │                                                        │
│ 项目        │   工作流画布          ╭────────────────────────────╮   │
│ 工作流      │                       │ 资料研究 · Codex       ↗ × │   │
│ 智能体      │  拆分 → 资料研究      │ 市场概况 / 当前工作与目录  │   │
│             │     ╲                 ├────────────────────────────┤   │
│ 项目列表    │      → 案例分析       │ ▸ 交付物 1                 │   │
│ …           │                       ├────────────────────────────┤   │
│             │                       │                            │   │
│ 会话列表    │   原画布仍可操作      │ 原有消息、工具与权限请求   │   │
│ …           │                       │                            │   │
│             │                       │                            │   │
│             │                       ├────────────────────────────┤   │
│ 设置 / 版本 │                       │ 原有输入框、配置与发送     │   │
│             │                       ╰────────────────────────────╯   │
└─────────────┴────────────────────────────────────────────────────────┘
```

图中的浮框覆盖画布的一部分，不占独立布局列。

| 区域         | 内容与规则                                                   |
| ------------ | ------------------------------------------------------------ |
| 头部         | 当前工作标题、真实状态、执行者；保留关闭和“打开完整会话”入口 |
| 上下文       | 工作目录等必要信息；多项工作时才提供紧凑切换入口             |
| 交付物折叠区 | 默认收起，显示实际成果数量，展开后查看成果、输入与交接       |
| 消息区       | 复用已有时间线、工具折叠、权限与输入请求，占剩余空间         |
| 底部输入区   | 复用已有输入、附件、命令、技能、模型配置与发送策略           |

浮框正文有明确的滚动边界，底部输入区保持可见。交付物展开区限制高度，长清单在区内滚动，不能把输入框挤出视口。桌面只对透明度和小幅位移动画，约 `150–200ms`；减少动态效果时取消位移动画，不动画改变画布宽度。

窄屏沿用现有浮框的响应式方式：小于 `768px` 时可覆盖可用画布区域，保留关闭入口和完整输入。长路径、长标题及文件名允许换行或省略后查看，不产生整页横向滚动。

## 3. 交付物是框内折叠区

交付物和聊天共用浮框宽度。展开后按实际内容展示以下分组，不再并排增加 Inspector。

| 分组       | 展示内容                                                          |
| ---------- | ----------------------------------------------------------------- |
| 本工作交付 | 当前工作已确认的成果文件；复用成果标明真实工作、Agent 与 Run 来源 |
| 输入材料   | 当前工作绑定的说明与上游成果，来源信息按需展开                    |
| 分工材料   | 拆分说明、内部工作清单与已受理分工，协议文件使用易读名称          |
| 交接       | 接收方、真实校验结果、阻塞与缺失项                                |

“交付物 N”只统计当前工作范围的实际成果。输入、`tasks.json`、`dispatch.json`、目录总文件数和文件变更数不混入计数。主会话汇总其他 Agent 的成果时写明来源，不标成主会话自己产出的文件。

尚无成果时可展开查看已有输入和真实等待原因。未产出、等待上游、交接失败和读取失败分别表达；例如“缺少用户画像.md，汇总尚未开始；案例对照已保留”。文件多时展开其余项，不为每个文件再套摘要卡片。

展开状态按准确会话和工作范围保存，切换工作时不把其他会话的文件带过来。

## 4. 看文件与打开完整会话

点文件复用已有文件查看器和下载能力，在当前浮框内进入文件查看状态，并提供返回交付物列表的入口。文件查看与列表切换保留原消息滚动、输入草稿和交付物展开状态；聊天和输入状态不因预览而销毁。

大文件或需要更多操作时，可打开完整会话或已有完整文件查看入口。完整会话沿用 `buildWorkspaceSessionHref`，精确定位 `/workspaces/:workspaceId?session_id=:sessionId`；远端保留 Host 路径。这个入口是按需操作，点击 Node 本身仍留在画布。

完整会话的 Inspector 继续使用原有标签、收起和宽度规则。本方案不要求在窄浮框中重建这套工具区。

文件缺失、删除或无权限时保留引用和来源，显示真实错误；删除记录只展示路径和事实，没有可下载文件。引用读取当前可访问的文件，不承诺历史字节快照。成果引用与 Agent 新增、修改、删除的文件记录分别展示，不新增 diff 产品。

## 5. 切换工作和关闭浮框

Node 只有一项实际工作时，一步打开该 Session；多项工作时恢复上次查看项，首次优先活跃项，多项活跃按稳定顺序选择。具体内部工作入口始终定位自身会话，不能找最近会话代替。

点击其他 Agent Node、内部工作、候选或主 Agent 时，更新同一个浮框。聊天、状态、目录、配置、交付物和合法操作一起切换到准确 Workspace/Session/Host/工作范围。共享目录不等于共享会话，旧异步请求不能覆盖新选择。

沿用原会话的草稿和配置恢复规则；消息滚动、交付物展开与文件查看位置按范围保留。从分工清单或复用来源进入时，提供返回来源的紧凑入口，回到准确对象，不重建会话。

点关闭或按 Esc 收起浮框，回到同一画布位置，焦点返回触发对象；内层菜单或文件查看先处理自己的 Esc。非模态浮框不锁住焦点，用户仍能操作画布。点击画布空白只进行画布选择或平移，不自动丢弃正在查看的会话。

关闭、切换或打开完整会话都不停止 Agent，也不等于撤销工作流。已有发送队列、草稿和运行状态仍由原会话与 Runtime 管理。

## 6. 没有会话的对象

| 对象            | 点击后的内容                                                       |
| --------------- | ------------------------------------------------------------------ |
| 尚未启动的工作  | 在同一浮框说明等待原因，不新建空会话，不借用同 Node 其他工作的会话 |
| Arena 容器      | 原候选与采用界面；点击具体候选才显示其会话                         |
| Human Gate      | 真实待确认内容与批准/拒绝入口，不伪造审批聊天                      |
| Condition、Edge | 对应判断或交接信息，有真实会话引用时提供准确入口                   |

编辑 Node 配置继续沿用原有编辑浮层。运行时查看聊天与编辑冻结后的工作流不是同一个操作。

## 7. 聊天与流转的关系

发送、排队、继续和停止沿用现有 `RuntimeActionPolicy` 与原生 Agent 能力。浮框不能制造底层不支持的交互、复制发送队列或绕过配置恢复。

用户可在原会话讨论；正式重做并影响后续流转仍需明确管理操作、新 Run 及准确范围。聊天中的“再做一遍”不等于 Runtime 已受理，文件出现也不等于交接成功。

查看复用来源应明确原 Run、工作和会话；查看本身不创建当前执行。Agent 权限请求使用原会话组件，Human Gate 使用真实待办，聊天补充要求不构成人工批准。

## 8. 原型与实施边界

[静态原型](./interaction-preview.html)演示“画布保留 → 右侧会话浮框 → 展开交付物或看文件 → 关闭回到画布”。聊天区域只标注已有组件的复用位置，消息和输入均是演示，不能作为新生产聊天组件的实现来源。

真正接入时，如果现有聊天内容依赖页面路由，应先把可复用的会话内容与必要 Provider 边界从页面组合中提取出来，由完整会话和浮框共同使用。保留原消息、输入、权限、配置与草稿契约，避免复制 `WorkspacesMainContainer` 的实现。此文档不将尚未接入的能力宣称为已完成。
