## 本轮范围

本轮按已确认的设计实施产品接入。[静态原型](./interaction-preview.html)只说明位置与交互，生产界面使用已有 React 会话组件。

目标是点击工作流中的具体工作，在画布右侧浮框中使用已有聊天能力。浮框内提供可展开的交付物；打开完整会话是按需入口。

## 实施顺序

### 1. 确认共享会话内容边界

- 梳理现有聊天组件所需的 Session、Workspace、Host 与 Runtime 上下文。
- 保持 canonical 消息、输入队列、草稿与配置恢复的唯一责任方。
- 如需提取组件，先让现有完整会话继续使用提取后的共享实现，再将其接入浮框。
- 完整页与浮框只改变承载布局，不增加第二套会话记录或生命周期。

### 2. 接入原画布浮框

- 从 NodeExecution、内部工作、候选和主会话读取准确绑定。
- 点击已有 Session 的工作直接在同一浮框显示会话；无 Session 时显示真实等待原因。
- 保留画布 viewport，浮框无 Scrim、不锁背景操作；关闭后恢复触发对象焦点。
- 切换前按会话保存草稿与查看位置，旧请求不得覆盖新对象；关闭不停止 Agent。
- “打开完整会话”沿用原路由，精确传递 Session 与 Host。

### 3. 接入框内交付物

- 默认只显示“交付物 N”折叠行，展开后按成果、输入、分工与交接分组。
- 交付物和文件查看状态使用同一浮框宽度，长清单限制高度，输入区保持可用。
- 使用已有文件查看器与访问 API，文件返回后恢复列表、草稿和消息位置。
- 复用成果和主会话汇总标明真实来源，不把输入或协议文件计入成果数量。

### 4. 接顺五种玩法

- 分工清单、候选、审核与主会话使用同一浮框，内部工作不是看板 Task。
- 非 Agent 对象继续使用真实决定、判断或交接界面。
- 重试、人工决定和选胜沿用真实受理规则，不由聊天 UI 直接推进下游。
- 不重新打开已完成的文件驱动工作流 P0，不修改已冻结运行图。

## 实施检查清单

- [x] 提取共享会话内容，完整会话页与工作流浮框使用同一实现。
- [x] 让 Node、内部工作、Arena 候选与主会话准确打开已有 Session。
- [x] 增加只读文件来源投影，交付物默认折叠，文件在原浮框内预览。
- [x] 保留按工作选择、草稿、滚动位置及 Host 范围，拒绝迟到响应串会话。
- [x] 更新组件契约和定向测试，检查现有画布、完整会话与文件预览。

实施不增加数据库迁移，不启动真实 Agent，也不执行本机发布构建。

共享内容入口为 `WorkspaceConversationContent`，准确会话加载入口为 `WorkspaceSessionConversation`。完整会话页保留原页面组合与 Inspector；浮框通过同一内容组件呈现原有时间线和输入框。

新增 `GET /api/workflow-runs/{run_id}/file-context`，可按 `node_execution_id` 读取准确工作的文件角色及来源。接口只读数据库快照，不扫描目录、不读取文件字节、不执行工作流状态推进。文件内容仍通过原有查看与下载接口，在用户打开后读取。

执行来源单独返回 Run、Workspace、NodeExecution 与 Session，不依赖是否存在文件。复用旧批次成果时，先验证该执行属于当前 Run 已受理的工作，再打开原会话；没有成果文件也可查看。来源会话只读，不能发送、编辑重跑或修复脚本。

文件和工具日志都在同一浮框内查看，原聊天保持挂载。打开预览后聚焦返回操作，返回时恢复原触发对象；Esc 先返回聊天，再关闭浮框。完整会话页的工具日志继续使用原 Inspector。

草稿保存与删除按原 Host/Session 顺序执行，快速关闭会保存尚未落盘的输入。旧会话实例的迟到发送或排队回执不能删除重新打开后的新草稿；远程浏览器保存的会话草稿也按 Host 隔离。

## 数据责任

| 内容                         | 负责方                                     |
| ---------------------------- | ------------------------------------------ |
| 消息、流式输出、权限与输入   | 现有会话投影、时间线与原生交互组件         |
| 草稿、配置、发送、排队与停止 | 原会话状态、配置恢复与 RuntimeActionPolicy |
| 工作、候选和会话对应关系     | 现有运行投影与真实绑定                     |
| 交付物和来源                 | 现有交付/交接文件引用；不足时补只读投影    |
| 展开、选择、文件与滚动位置   | 按准确会话和工作范围管理的视图状态         |
| 画布 viewport                | 原画布状态，不因浮框开关而重置             |
| 文件访问                     | 已有 Workspace/Workflow 查看器和 Host 范围 |

不新增工作流专属聊天表、发送队列或会话路由。文件内容不另存 localStorage。若投影类型需要扩展，仍从 Rust 定义生成 TypeScript 类型。

## 验收重点

| 场景                                     | 应有结果                                              |
| ---------------------------------------- | ----------------------------------------------------- |
| 点击已执行的具体工作                     | 一步在右侧约 440px 浮框中显示准确会话                 |
| 浮框打开                                 | 画布仍可操作，尺寸与 viewport 不变，无 Scrim 或模糊   |
| 从侧栏、普通任务和工作流打开相同 Session | 相同历史、配置、草稿与输入规则，呈现容器可不同        |
| 切换工作、候选或主会话                   | 同一浮框切换，Session、目录、状态与文件不串范围       |
| 默认交付物区                             | 收起为一行，数量只统计真实成果                        |
| 展开交付物或长清单                       | 聊天与输入仍可用，浮框不横向扩张                      |
| 打开文件后返回                           | 原列表、草稿和消息位置保留                            |
| 关闭或 Esc                               | 先处理内层查看/菜单，再关闭浮框；焦点回到准确触发对象 |
| 操作画布空白                             | 正常选择或平移，不意外关闭正在查看的会话              |
| 关闭、切换或打开完整会话                 | Agent 与原队列继续按真实状态工作                      |
| 尚无 Session                             | 显示真实等待，不创建假会话或启动 Agent                |
| 打开完整会话                             | 准确的已有路由，Host 范围保留                         |
| 查看复用成果                             | 来源明确，可看原会话，不冒认当前 Run 已执行           |
| 人工决定、选胜、重试与停止               | 依现有 action gate 和真实受理结果                     |
| 窄屏、键盘与减少动态效果                 | 输入完整、无横向溢出、焦点不被非模态浮框锁住          |
| 原完整会话页                             | 聊天与 Inspector 原有行为保持完整                     |
