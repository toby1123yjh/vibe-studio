## 1. 目标与当前状态

日期：2026-10-28。状态：**共享输入区、发送链路、消息与过程展示、虚拟列表和滚动协调已实施，已完成前端浏览器回归**。

对话窗口以阅读和输入为主。用户按下发送后立即看见自己的消息；智能体工作时能看懂当前活动；工具详情、思考、设置和文件在需要时展开；阅读历史、调整宽度、继续输入互不打断。

独立会话、任务会话、工作流主会话和节点会话继续复用现有共享窗口。本文补充 [对话重构设计](./design.md) 的交互部分，原有协议、审计、历史和原生能力契约继续适用。

本次对照的是 DeepSeek Harness 的 Web 客户端源码。参考快照为 `deepseek-ai/deepseek-harness@22ddee3792402c3e70ec5f86a63c3e3e895a2f60`，本地位于 `docs/daily-radar/.cache/deepseek-ai__deepseek-harness`。下文区分参考源码事实、改造前的问题与已落地的行为；验证结果与边界见第 6 节。

## 2. 从参考源码学到什么

| 参考机制               | 源码事实                                                                                            | Vibe Studio 的应用方向                                             |
| ---------------------- | --------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------ |
| 提交与编辑分开         | `input/machine.ts` 的普通提交生成独立 attempt，先捕获发送内容，再提交草稿清理；网络请求期间仍可编辑 | 一次提交使用完整快照；发送后可以输入下一条；失败恢复按草稿版本判断 |
| 编辑器直接交付当前内容 | `input/editor/keymap.ts` 直接调用提交处理器，并处理输入法、候选菜单和长按 Enter                     | 发送接收当前编辑器快照，减少为了刷新 React 闭包而做的同步提交      |
| 消息身份稳定           | `ChatFlow.tsx` 将消息、本地回显和运行状态放进同一 keyed sibling list                                | 本地消息确认前后保持连续；稳定历史与正在变化的尾部分开更新         |
| 节点独立订阅           | `ChatNodeSeat.tsx`、`ChatGroupSeat.tsx` 分别订阅节点和组的状态                                      | 历史正文、折叠摘要、输入框各自更新，减少无关渲染                   |
| 执行过程渐进展开       | `ChatGroupSeat.tsx` 使用活动摘要和局部展开；`ReasoningRow.tsx` 独立管理思考展开                     | 工具和思考保持紧凑、可查；摘要来自真实事件；展开状态稳定           |
| 阅读意图独立于滚动位置 | `use-scroll-follow.ts` 区分用户滚动与程序跟随；`use-chat-scroll.ts` 协调提交、加载历史和布局变化    | 统一处理底部跟随、历史锚点、展开和尺寸变化                         |

DeepSeek Harness 也使用 Lexical。更换编辑器并非此次改造的前提。它的插件体系、整轮折叠策略和复杂折叠动画有各自适用条件，本次按现有组件和业务边界选用。

## 3. 改造前的问题与本次调整

| 位置                            | 改造前的情况                                                                       | 本次调整                                                     |

| `KeyboardCommandsPlugin.tsx`    | Enter 序列化 Markdown 后通过 `flushSync(onChange)` 刷新 React，再调用发送          | 直接传递提交快照，保留最后一个字符、输入法和菜单仲裁的正确性 |
| `ConversationListContainer.tsx` | 本地发送状态变化触发 `useLayoutEffect`，同步调用历史条目派生、回显投影和时间线派生 | 本地回显独立更新；发送首帧避免重算整段稳定历史               |
| `CreateChatBoxContainer.tsx`    | 先等待工作空间创建，成功后才建立回显并导航                                         | 创建阶段也有即时反馈；成功绑定正式会话时连续交接             |
| `ChatBoxBase.tsx`               | 配置、状态、上下文、正文、操作和提示分为多层，多处允许换行                         | 压缩常驻层级，明确文本区与操作区，按容器宽度安排控件         |

现有按块订阅、流式 Markdown 分段、虚拟列表、草稿版本保护及滚动锚点，都是继续优化的基础。

## 4. 界面与交互

├──────────────────────────────────────────────────────────────┤
│                                                              │
│  用户消息：自然宽度、轻量背景                                  │

│  ▸ 思考摘要                                                  │
│  ▸ 执行过程 · 正在读取 src/main.ts                            │

示意图中的执行过程、思考和交互区域按实际内容出现。正文与输入区共享水平对齐规则；底部留出清晰间距，输入区占正常布局空间。

会话标题区承载项目、任务和路径，输入区专注本次消息。新建会话仍提供项目选择，关联任务已确定时显示其上下文。已建立的会话保持智能体身份绑定。

### 4.2 输入区：正文一块，操作一排

- 文本区自动增高，达到高度上限后仅文本区内部滚动；发送和停止始终可见。
- 底部左侧依次安排附件、智能体身份、完整模型和有效思考等级；更多设置通过现有弹出入口访问。原生能力决定可用选项。
- 狭窄容器保留现有更多菜单，模型名称可截断并提供完整提示；左侧控件在自己的区域换行，右侧始终保留发送或停止的位置。
- `/`、`@` 等现有输入能力使用锚定输入框的分类浮层；菜单选项的 Enter 与消息发送互不混淆。
- Enter 默认发送，Shift+Enter 换行。中文输入法确认候选、长按 Enter、点击发送均须有明确且一致的行为。
- 附件、权限和提问属于条件区域。提问或审批使用自己的明确动作，普通 Enter 保持当前输入语义。

### 4.3 发送：立刻看见，失败能处理

提交时捕获文本、附件、技能、当前有效配置与草稿版本。前端立即建立本地用户消息、清理本次草稿并更新发送状态；这些反馈先于网络结果。编辑器保留焦点，用户可以继续输入。

发送区使用一条紧凑的条件活动提示：提交后立即显示发送中，智能体运行时切换为处理中，停止请求显示正在停止；这几个阶段保持同一位置。停止按钮保留清楚的停止图形。等待审批、提问或运行结束后退出处理动效；没有活动时不保留空栏。新建会话与已有会话共用该样式，不延迟发送；开启减少动画时保留静态指示和状态文字。

已有会话沿用本地发送记录；新建会话需要一个短期创建提交标识，在原入口显示相同的消息反馈。取得正式 workspace/session 后将这条记录绑定过去，再交接到共享对话窗口。创建失败保留在原入口，按草稿版本恢复。

| 阶段                   | 用户看到什么                                 | 处理规则                                                             |
| ---------------------- | -------------------------------------------- | -------------------------------------------------------------------- |
| 本地已提交，等待服务端 | 自己的消息立即进入历史，显示轻量发送状态     | 阻止同一次提交重复执行；下一条草稿可继续编辑                         |
| 服务端已接受           | 消息连续保留                                 | 按 HTTP 确认的 `agent_run_id` 与正式用户块关联；正式块可见前保留回显 |
| 智能体运行中           | 正文尾部显示真实活动；停止入口可用           | 发送状态与运行状态分别管理；支持排队时才显示对应动作                 |
| 确认发送失败           | 在输入区显示原因，恢复或保留可重新发送的内容 | 仅在没有更新草稿时自动恢复；有新内容时保留新内容                     |

确认时保持用户消息外层的渲染身份，避免回显被移除、正式消息随后才出现。流式事件先于 HTTP 确认时，沿用现有请求与 run 的关联约束，不按文字猜配。

### 4.4 消息、工具与思考：内容层级清楚

- 用户消息按内容自然排布，轻量背景和有限内边距，避免整行大边框；长文本正常换行。
- 智能体正文优先展示。复制等次要操作弱化，键盘聚焦时仍可发现。
- 相邻、同一运行和父级中的工具使用一行执行过程摘要，展示当前工具或路径；正文、审批或提问出现时保留原本的先后顺序。
- 默认摘要省去工具调用次数和完成统计。展开后查看各工具、参数、结果、文件和原始详情。
- 思考独立折叠，能展示真实首行摘要时才展示；内容缺失时保留实际状态。工具和思考使用同一套展开图标、焦点样式和间距。
- 新片段、刷新、尺寸切换保持手动展开选择；完成不会突然收起用户正在阅读的内容。
- 工具失败在对应步骤标明；整次运行的失败取自运行状态。重试、停止、等待输入都有各自含义。

### 4.5 滚动与流式显示：尊重阅读位置

底部跟随、主动阅读历史、加载旧页、展开详情、调整窗口大小，共用现有滚动协调与锚点机制。历史和活动尾部现在处于同一 keyed 虚拟列表；范围提取器固定保留最后 32 行，避免运行开始或结束时把行搬到另一个 DOM 父级并重挂载正文。

| 操作或事件           | 预期行为                                                      |
| -------------------- | ------------------------------------------------------------- |
| 在底部接收新内容     | 跟随活动尾部，流式合帧更新；避免每个 token 都启动新滚动动画   |
| 主动向上阅读         | 暂停自动跟随，出现回到底部入口                                |
| 用户发送消息         | 提交后跟随自己的新消息；后续主动上翻能立即打断跟随            |
| 加载旧消息或展开工具 | 保持可见块 ID 和块内偏移，避免内容突然移位                    |
| 输入区变高或浮框变宽 | 底部用户保持底部；历史阅读者保持阅读锚点                      |
| 关闭后重新打开       | 沿用会话草稿和现有阅读/展开偏好；未确认的发送仍只保留一条回显 |

已完成的 Markdown 保持稳定，仅更新活动块；打开工具详情才加载大正文。`ChatDisclosure` 统一展开按钮、状态图标和内容边线；交互主要使用轻量颜色与图标过渡，支持 reduced-motion。展开造成的高度变化交给现有锚点协调，不增加整块高度动画引擎。

### 4.6 宽度与外壳

继续使用 `ConversationWindow`、`FloatingPanel` 和 `CONVERSATION_PANEL_SIZING`：当前默认 900px、最小 480px、最大 1350px，实际受可用视口约束。任务、工作流与独立会话共享尺寸偏好。

输入框响应自己的容器宽度。调整宽度时，正文和输入一起重排；Inspector 保证会话可读空间，空间不足时使用显式切换。长代码或表格可以局部横滚，整个会话与输入框保持无横向溢出。

## 6. 验收方式

复用 `tests/workflow/specs/workflow-instant-send.spec.ts` 和现有隔离浏览器页面，按改动增加必要用例。模拟慢接口验证即时反馈，与真实 CLI 首次输出等待分别记录。

- 接口被刻意延迟时，用户消息、输入清理和按钮反馈仍先出现；确认交接期间始终恰好一条用户消息。
- 中文输入法、候选菜单、最后一个字符、连续 Enter、附件和快捷键均不误发或丢内容。
- 失败恢复覆盖“输入框仍空”和“用户已写下一条”；关闭重开、切换会话和跨 Host 保持作用域正确。
- 流式回答与长工具输出期间，输入焦点、展开选择和阅读位置稳定。
- 默认宽度、最小宽度、Inspector 开合及较小视口均无输入框裁切或整个窗口横滚。
- 在记录了机器与浏览器环境的条件下，测量空历史、100 块和 500 块活动窗口的 Enter 至反馈呈现；历史总量更大时仍验证分页。目标是交互反馈 p95 在 100ms 内，结果以实测记录为准。
- 使用 Performance trace 或 Event Timing 核对提交首帧的主线程工作；下一帧回调仅作采样，不能替代实际呈现时序。现有“接口返回前已显示”的断言不足以证明低延迟。

### 6.2 真实页面与运行版本核对（2026-10-28）

本机 `http://localhost:3000/` 使用当前工作树的 Vite 前端；`3001` 上的 API 服务仍为官方 npm `2.0.0-beta.12`。该发布程序也提供自己打包的旧页面，因此两个端口不能视为同一套前端。修改后端源码或刷新浏览器，都不会更新正在运行的 npm 程序。

### 6.3 首次创建与页面交接复测（2026-10-29）

继续在 3000 的实际源码页面测试，确认此前仍遗漏了首次创建路径：已返回的 Run 没有进入目标会话缓存；路由更新 URL 后，旧创建框仍会短暂保留，但绑定正式会话时已将旧框的回显删除。两者共同造成发送按钮临时回到空闲、用户消息短暂消失。之前只检查继续发送和目标页面，未覆盖实际路由交接。

现在首次创建保存接口返回的真实 Run，并预取真实 Session 与执行配置；创建回显在目标作用域绑定后，仍在旧创建框保留到其卸载或切换作用域，再释放准确的源记录。目标回显继续由正式用户消息到达来结算，不按文字匹配，不增加运行计时器。

实际 Codex 新建会话逐帧采样中，约 34ms 出现用户消息，165ms 更新路由时消息仍在，266ms 进入目标会话的运行控件；此次采样未再出现之前约 130ms 的空白。随后继续发送，约 36ms 出现回显与按钮三点动画，170ms 切换为运行控件且动画保持，约 8.4 秒回复完成后退出。这是本机的两次实测记录，不作为生产延迟保证。

同时将思考/工具摘要的渐变限制在文字实际宽度，避免动效在空白 flex 空间中移动而难以察觉；共享折叠按钮明确使用 120ms 过渡属性，兼容 reduced-motion。原有 3001 后端仍是 npm beta.12，后端路由修复需要发布后替换程序才能生效。

### 6.4 看板会话状态

状态放在会话标题前的固定 20px 位置，图形为 14px，避免图标散落在卡片右侧。运行使用缓慢旋转的细环，等待使用暂停图形，完成使用小对勾，失败和取消保留不同图形。运行、等待和失败使用语义淡色背景；悬停与辅助名称提供完整的本地化状态，卡片不常驻状态文字。

任务卡片汇总各类活动的数量，隐藏预览中的执行仍参与计数。运行和等待可同时显示，历史失败不会掩盖正在运行的会话。状态不改变任务所在列；拖拽预览沿用相同尺寸，减少动态效果时保留可识别的静态图形。

### 6.5 输入区活动提示调整

根据后续反馈，前述实测版本中按钮内的三点改为共享的条件活动行：20px 淡色图形区、14px 细环，以及当前动作文字。发送、运行和停止保持同一位置；有真实 Todo 时显示其内容，审批、提问和空闲状态退出活动提示。没有活动时不保留空栏。

按钮只表达动作：发送、创建、停止。停止使用方块图标，过程文字集中在活动行；运行中不再用停止按钮承载跳动的三点。减少动态时保留静态开放圆环与文字。新建会话和已有会话共用组件，沿用已验证的实际 Run 交接、即时回显及草稿管理。
